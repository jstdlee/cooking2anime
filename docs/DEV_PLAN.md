# cooking2anime — Development Plan

Design: [DESIGN.md](DESIGN.md) · Test rules: [TESTING.md](TESTING.md)

## Principles for the plan

1. **Deep before wide.** One preset, one local stack and one cloud stack, each tuned
   and measured. A new provider or preset is only added after the existing ones pass
   every gate on the golden set.
2. **Walking skeleton first.** By M1 the whole pipeline runs end-to-end on fake
   providers in CI. Each later milestone swaps one fake for a real model, and the CI
   pipeline never stops being green.
3. **Each milestone ships a demo and its tests.** "Done" means the acceptance criteria
   are met, the tests required in TESTING.md are merged, and a demo artifact (video or
   board) is attached to the milestone PR.
4. **Spikes are time-boxed.** Each one answers a single question, records the answer in
   `docs/decisions/` (ADR format), and its throwaway code is deleted.

Estimates assume one full-time developer with a 24 GB GPU box and cloud credits.
Total ≈ 13 weeks to v1.

above; GoDraw is the chosen canvas either way.

## M0 — Repository foundation (week 2)

**Scope**
- `pyproject.toml` (Python 3.12, uv), package `c2a/`, `ruff`, `mypy --strict`,
  `pytest`, `pytest-socket`, `hypothesis`, pre-commit.
- CI (GitHub Actions): lint → type → unit → integration-fake → board-schema. Must
  finish in under 8 min.
- `c2a/config.py`: pydantic models for `configs/default.yaml`. Unknown keys are an
  error, and every option is documented.
- `c2a/core/manifest.py`: run folder, atomic writes, state machine, content-hash
  cache keys.
- `c2a doctor` (ffmpeg present, Python deps; GPU and ComfyUI checks are stubbed).
- Test fixtures generated by script: `tests/fixtures/make_fixtures.py` uses ffmpeg
  testsrc2 to build 6 s clips at 29.97 fps (CFR and VFR versions), with a hard cut at
  3.2 s, a sine tone, and burned-in "SAMPLE TEXT".

**Acceptance**
- `c2a run fixture.mp4` creates a run folder, a manifest and the state transitions.
- Coverage of `c2a/core` ≥ 90%.

## M1 — Walking skeleton on fakes (week 3)

**Scope**
- Stage graph and scheduler (`c2a/core/pipeline.py`), with resume and cache-hit
  skipping.
- **Every stage implemented end-to-end against fake providers:** analyze (real
  ffmpeg + real TransNetV2 on CPU), describe (`FakeVLM` returns schema-valid JSON),
  preview, gate (`c2a approve`), restyle, generate, post (real ffmpeg concat/encode),
  audio (`FakeFoley`/`FakeVoiceFX` make tones), export.
- **Timeline engine:** chunking with the 4n+1 rule, shared boundaries, retime maths.
- Report JSON.

**Acceptance**
- The fixture goes all the way to an mp4 in CI. Output duration = source duration
  ± 1 frame, the source audio is absent, and a new audio track is present.
- `c2a rerun --chunk` re-runs only that chunk; the test checks that no other cache
  entry was touched.
- Property tests on the timeline pass at 10k examples.

---

## M2 — Board v1: GoDraw canvas (week 4–5)

**Scope**
- `c2a/board/model.py`: typed models for the `.tldr` records we use (document, page,
  frame, image, note, geo, arrow, asset), `meta.c2a` ownership.
- `c2a/board/projector.py`: manifest → board (all three pages, stable layout, status
  colours, frame strips, `▶ open` links to mp4s, thumbnail budget).
- `c2a/board/reader.py`: approval through sticker `parentId`, prompt-note diff,
  re-run stickers. Every input is validated.
- `c2a/board/sync.py`: optimistic read-merge-write, 2 s batching, `c2a watch`, `c2a
  board open|rebuild`, `c2a open`.
- Node-based validator in CI: `tools/tldr-validate` checks every board we produce
  against `@tldraw/tlschema` at the pinned version.

**Acceptance**
- A user's own shapes survive 100 engine rewrites byte for byte (property test).
- In the simulated-user e2e test (a script edits the file the way GoDraw would): drag
  the sticker in → the run resumes within 3 s.
- Real GoDraw e2e test on Linux under Xvfb (automation socket, pinned commit): open the
  board, move the sticker, and the approval lands. Runs in CI; a macOS and Windows manual
  checklist is signed off once per release.
- Every board passes the tldraw schema validator.

## M3 — Analyze + describe, real (week 6)

**Scope**
- VFR→CFR normalization tested on real phone footage (iPhone VFR, Android 60 fps).
- Qwen-VL local backend + one cloud VLM backend. Prompt + JSON schema, closed
  vocabularies, retry on invalid JSON.
- Prompt builder with token counting from the real Wan tokenizer, drop order, and
  per-chunk overrides.
- **Golden set v0:** 5 owned or CC0 cooking clips (30–60 s), each with a hand-written
  reference description.

**Acceptance**
- Over the golden set, 100% of VLM output is schema-valid, and the beats cover each
  chunk with no gaps.
- Human check: ≥ 90% of beats are rated "accurate" (rubric in TESTING.md).
- Prompt snapshot tests are checked in.

---

## M4 — Preview, gate and restyle, real (week 7–8)

**Scope**
- ComfyUI backend (workflow JSON + `bindings.yaml`, WebSocket progress, retries,
  model-hash checks in `doctor`). fal backend for the same model.
- `shinkai_food` preset: tune the prompt, LoRA and realism on the golden set.
- Sample selection, `style.lock.json`, restyling every keyframe with a style
  reference, keyframe QA (style similarity, structure, OCR).
- `c2a calibrate` v1 (style and structure thresholds).

**Acceptance**
- 0 OCR text boxes across all restyled golden keyframes (the burned-in-text clips are
  included).
- Within a shot, the median style similarity between keyframes is ≥ the calibrated
  threshold.
- A person can approve on the board in under 2 minutes (timed in the usability check).

---

## M5 — Generate, real (week 9–10)

**Scope**
- Wan FLF2V workflow (local) + fal backend, seeding per chunk, boundary SSIM check.
- VLM motion judge, RAFT flicker, a retry policy that simplifies the beats after the
  second retry, `flagged` handling.
- GPU queue locally and a parallel pool in the cloud, with a cost meter in the report.

**Acceptance (golden set)**
- Boundary SSIM ≥ 0.90 on 100% of chunks.
- ≥ 85% of chunks pass motion and flicker without being flagged.
- Two runs with the same seeds give identical outputs on the local stack
  (bit-for-bit where the provider is `deterministic`, otherwise metrics within 1%).

---

## M6 — Post + export (week 11)

**Scope**
- RIFE retime to an exact frame count, SeedVR2 for 1080p, LUT + grain, encode
  presets for 16:9 and 9:16, HTML report.

**Acceptance**
- Duration within ±1 frame on every golden clip, at both 720p and 1080p.
- `ffprobe` checks: resolution, pixel format, codec profile, faststart.
- Flicker after post ≤ flicker before post + 0.005.

---

## M7 — Audio (week 12)

**Scope**
- HunyuanVideo-Foley per shot with windowing and crossfades, cue → prompt mapping
  (`sound_cues.yaml`).
- Drama 3 VoiceFX (Fish API + local server): event selection rules, Whisper word
  guard, placement, gain.
- Mix: loudness normalization to EBU R128, true-peak limiter, no-audio mode.

**Acceptance**
- 0 words detected in any voice clip shipped in golden outputs.
- Loudness −14 ± 1 LUFS and TP ≤ −1 dBTP on every golden output.
- Human sync rating ≥ 4/5 on chop and sizzle moments (rubric).

---

## M8 — Hardening & v1 release (week 13)

**Scope**
- Failure injection: ComfyUI crash, cloud 429/5xx, disk full, interrupted run, board
  corrupted → resume or a clear error each time.
- `c2a doctor` complete, docs (README quickstart, config reference generated from
  pydantic, a "tuning a workflow on the ComfyUI canvas" guide).
- Golden set expanded to 10 clips; metrics baseline frozen as `v1`.

**Acceptance**
- An unattended batch of 5 golden clips finishes on both stacks with a report and no
  manual steps after approval.
- Every failure injection ends in resume or a documented error.
- Tag `v1.0.0`.

---

## After v1 (only once v1 gates stay green)

Ordered by expected value: pose-control fallback for flagged chunks → a second preset
→ 4K upscale → another cloud vendor → batch-folder canvas page.
